# Public API and compatibility policy

This page says what you may depend on and what Trunk promises about it. It is enforced by
`tests/Architecture/PublicApiTest.php`, so it cannot drift from the code.

## What is public

A type is **public API** only if its docblock carries the `@api` tag. The complete list is at the
end of this page and is generated from those tags.

**Everything else is internal**, whether or not it is `public` in PHP: do not extend it, construct it, or
type-hint it, and expect it to change or disappear in any release, including a patch release. A method
tagged `@internal` inside an `@api` class is internal too. The usual case is a constructor whose
collaborators are internal types: you receive such services from the container (inject them), you do
not call `new` on them.

Rules the tests enforce:

* An `@api` type is an interface, an enum, or a `final` class. There is no public base class to extend
  (the five abstract classes are all `@internal`).
* An `@api` signature never exposes a type that is not `@api`, unless the method is tagged `@internal`.
* A type is never both `@api` and `@internal`.
* This list is regenerated with `php tools/api-list.php --write`.

## Stable contracts that are not classes

These are part of the promise as well:

* The **format of `trunk.php`** (a returned module list) and of `extra.trunk.capability` metadata in a package's `composer.json`.
* **Config keys** documented in the config files that `trunk` publishes into `config/`.
* **Container tags** for extension: `trunk.lifecycle` (`LifecycleAware`), `trunk.error_reporter` (`ErrorReporter`), `trunk.health_check` (`HealthCheck`), `http.error_renderer` (`ErrorRenderer`), `orm.scope` (`Scope`), `auth.policy` (`Policy`), `auth.ability` (`Ability`), and `ContainerBuilder::bindDefault()` for replacing a core default.
* **Error codes** (`ErrorCode` values and your own `HasErrorCode` codes) and the JSON error shape `{"error":{"code","message","requestId"}}`.
* **Validation**: the attribute vocabulary (`Required`, `Email`, `Length`, `Range`, `Items`, `OneOf`, `Pattern`, `Date`, `SameAs`, `RequiredIf`, `Each`, `Url`, `Uuid`, `Ip`, `Sensitive`, `From`, `ListOf`), the `validation` config keys (`mode`, `requests`, `build`), the error code `VALIDATION_FAILED` and its `422` body `{"error":{"code","message","requestId","details":{"fields":{"<path>":["message"]},"rules":{"<path>":"<rule code>"}}}}` (thrown as `Trunk\Error\ValidationException`), and the rule codes in `rules` (`required`, `type`, `email`, `min_length`, `max_length`, `min`, `max`, `one_of`, ...).
* **`trunk` command names and their documented options**.

Not part of the promise: the contents and layout of `build/` (regenerated by every build), generated
code, log message wording, exception message wording, and the output text of commands.

## Versioning

* Trunk uses [semantic versioning](https://semver.org) for the public API above. Every package in this repository is released together with the same version number, and packages depend on each other with `^` constraints on that version.
* **While the version is 0.x** a minor release (0.1 to 0.2) may change public API; a patch release (0.1.1) never does. Every change to public API is listed in `UPGRADE.md`.
* **From 1.0** public API changes only in a major release. A feature that is going away is first marked `@deprecated` (with what to use instead) for at least one minor release.
* Internal types follow no compatibility rule.
* Supported PHP: the versions the CI matrix runs (currently 8.4 and 8.5); dropping a PHP version is a minor release before 1.0 and a major one after.
